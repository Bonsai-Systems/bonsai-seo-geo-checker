BONSAI SEO/GEO CHECKER — LLM INSTRUCTIONS
=========================================

WHAT IT IS
Internal WordPress plugin by The Bonsai Digital Collective. It audits one URL for
technical SEO, meta, content, social, structured data, AI visibility (GEO) and
mobile performance (PageSpeed Insights), then asks Claude for a prioritised fix
list. Admin page: Tools > SEO/GEO checker. Capability: manage_options.
Version 1.2.0. WP 6.2+, PHP 7.4+. Prefix: bsgc / BSGC_.
Repo: https://github.com/Bonsai-Systems/bonsai-seo-geo-checker

FILES
bonsai-seo-geo-checker.php  bootstrap, duplicate guard, constants BSGC_VERSION/FILE/PATH/URL
inc/class-bsgc-updater.php   plugin-update-checker (GitHub release asset zip)
inc/class-bsgc-settings.php  Settings API page + BSGC_Settings::get()
inc/class-bsgc-fetcher.php   wp_safe_remote_get wrapper (SSRF-safe)
inc/class-bsgc-robots.php    RFC 9309 robots.txt parser
inc/class-bsgc-analyser.php  all checks + score(); CATEGORIES, SEARCH_BOTS, TRAINING_BOTS
inc/class-bsgc-pagespeed.php PSI v5 mobile
inc/class-bsgc-ai.php        Anthropic Messages API, JSON fix list, sanitise()
inc/class-bsgc-reports.php   hidden CPT bsgc_report
inc/class-bsgc-admin.php     admin page + AJAX + run_url()/report_url()
inc/class-bsgc-editor.php    edit-screen sidebar box + front-end admin bar link
assets/admin.js / admin.css  jQuery UI, print styles

AJAX ACTIONS (nonce "bsgc", manage_options)
bsgc_run_check, bsgc_run_pagespeed, bsgc_run_ai, bsgc_get_report, bsgc_delete_report

STORAGE (post meta on bsgc_report)
_bsgc_report (base checks), _bsgc_performance, _bsgc_ai, _bsgc_score (cache),
_bsgc_post_id (post the page belongs to; from the editor or url_to_postid)

ENTRY POINTS
Tools screen; ?bsgc_run=URL&bsgc_post=ID&_bsgcnonce=... (auto-runs if the nonce
is valid); ?bsgc_report=ID (opens a report). Editor box on public post types
(filter bsgc_post_types), published posts only. Admin bar "Check this page".
PSI and AI run in parallel, so each writes its own key. Do not combine them.

CHECK FORMAT
category, id, label, status (pass|warn|fail|info), message, weight, value, fix
message = finding only; fix = what to do (shown for warn/fail). fix is optional: older saved reports lack it.
Score: pass = weight, warn = weight/2, fail = 0, info = unscored.

SETTINGS (constant overrides the bsgc_settings option, non-autoloaded array)
BSGC_ANTHROPIC_KEY / anthropic_key
BSGC_PSI_KEY       / psi_key
BSGC_CLAUDE_MODEL  / model  (default claude-haiku-4-5-20251001)
Native Settings API page at Settings > SEO/GEO checker. No ACF dependency.
Saved keys are never printed back to the page; blank on save keeps the stored key.

RULES
- WordPress Coding Standards: tabs, Yoda conditions, escape all output.
- User-supplied URLs are fetched only through BSGC_Fetcher::get() (wp_safe_remote_get).
- JS inserts dynamic data with .text()/.attr(), never .html().
- Claude output must pass through BSGC_AI::sanitise().
- Never hardcode or log API keys.
- UK English in UI copy and prompts.
- Training crawlers are reported as info and never scored.
- Don't claim schema is missing based on static HTML alone. Refer users to
  Google's Rich Results Test.
- Update CHANGELOG.md and bump the version in both the plugin header and
  BSGC_VERSION for releases.

RELEASES
Bump both versions, push main, publish a GitHub release tagged vX.Y.Z. The
release workflow attaches bonsai-seo-geo-checker.zip; sites update from that
only. vendor/ is committed. Keep composer.json config.autoloader-suffix
(BonsaiSeoGeoChecker) and never copy vendor/ from another plugin, or the
Composer autoloader class clashes with other Bonsai plugins.
